# 国际化（vue-i18n）规范

完整细则、提取流程与反例见 `docs/国际化处理.md`。

## 必须遵守

1. **key 由工具按文件归集，不要手写重复 key**  
   业务文案集中在 `packages/locales/src/langs/zh-CN.ts` / `en-US.ts`（composition API 写法）；组件里写 `t('system.user.form.title')`，key 在源文件里不要重复命名空间。

2. **必须写完整短语，不要拼字符串**  
   `t('system.user.form.title')` 而非 `t('system.user') + ' - ' + t('form.title')`。复数 / 插值用 `t('system.user.selected', { count })`。

3. **按场景选用 API**
   - **模板内**：`{{ $t('system.user.title') }}` 或 `<i18n-t keypath="system.user.title" />`。
   - **`<script setup>`**：`const { t } = useI18n();` 后 `t('system.user.title')`。
   - **非组件配置（字典 / 校验规则）**：用 `useI18n` 在 composable 内获取；不要直接 `import i18n.global`。

4. **路由 / 菜单 / 按钮标题**  
   路由 meta 优先 `i18nKey`，由全局 `useAccess` 解析；菜单展示由 `usePreferences` 注入。

5. **后端双语字段**  
   使用 `@vben/utils` 的 `useLocale` + 后端返回的 `nameI18n` / `descriptionI18n` 字段；不要在前端做条件分支中英文。

6. **缺翻译时**  
   短期用 fallback（默认 zh-CN）；缺翻译条目必须落到 PR 描述里推动补齐，不要靠 `t('xxx', 'fallback')` 长期兜底。

## 提取与编译

```bash
# 提取与对齐所有语言文件
pnpm -F @vben/locales run extract
```

新增翻译后必须跑一次 extract，让所有语言文件 key 对齐；缺翻译会落到对应语言的 fallback。

## 正确示例

```vue
<script setup lang="ts">
const { t } = useI18n();
</script>

<template>
  <n-card :title="t('system.user.form.title')">
    <n-input :placeholder="t('system.user.form.name.placeholder')" />
  </n-card>
</template>
```

## 反例

- ❌ 在 Vue 模板里写死中文文案（如 `<n-button>提交</n-button>`）。
- ❌ 模板里 `t('system.user') + ' - ' + t('form.title')`。
- ❌ 在 `packages/locales/langs/*.json` 里手改——仓库采用 TS composition 写法，应编辑 `packages/locales/src/langs/*.ts`。
- ❌ `defineOptions({ name: 'Xxx' })` 但模板里写 `{{ $t('common.title') }}` —— 用 i18n key。
- ❌ 大量相同英文 defaultMessage 仅靠 description 区分不同中文含义（应改 key 名）。
