# 国际化处理（vue-i18n）

详细规范见 [`.ruler/i18n.md`](../.ruler/i18n.md)；本文件补充：提取工具链、键命名空间、新增语言流程、Locale 自动注册。

## 一、文件位置

- 文案源：`packages/locales/src/langs/zh-CN.ts`、`en-US.ts`（composition API 写法）。
- 模板里：`{{ $t('module.user.form.title') }}` 或 `<i18n-t keypath="module.user.form.title" />`。
- `<script setup>` 里：`const { t } = useI18n(); t('module.user.form.title')`。
- 非组件配置（字典 / 校验规则）：用 `useI18n` 在 composable 内获取；不要直接 `import i18n.global`。

## 二、键命名空间

- 业务模块前缀：`system.*`、`order.*`、`dashboard.*`...
- 子模块：`system.user.*`、`system.role.*`、`system.menu.*`...
- 语义粒度：`title` / `placeholder` / `empty` / `confirm` / `cancel` / `success` / `error`...

## 三、新增语言

1. 复制 `packages/locales/src/langs/en-US.ts` 为 `ja-JP.ts`（或其他 locale）。
2. 在 `packages/locales/src/index.ts` 的 `SUPPORT_LOCALES` 加入新 locale。
3. 在 `@vben/preferences` 的 schema 加入对应选项（`app.locale` 枚举）。
4. 跑 `pnpm -F @vben/locales run extract` 校对缺漏；缺翻译条目落到 PR 描述里推动补齐。

## 四、提取工具链

`pnpm -F @vben/locales run extract` 触发 `@intlify/unplugin-vue-i18n` 的 `vueI18n.extract`，从 `.vue` / `.ts` 静态扫描 `t(...)` / `$t(...)` / `<i18n-t>` 调用并写入对应 langs 文件。

## 五、后端双语字段

使用 `@vben/utils` 的 `useLocale` + 后端返回的 `nameI18n` / `descriptionI18n` 字段；不要在前端做条件分支中英文。

## 六、动态字典 / 平台 key

- 后端动态字典：业务页面内 `onMounted + request` 拉取并缓存，或用 `@vueuse/core` 的 `useAsyncState`；**不要**自造 `useDict`（仓库没有此 hook）。
- 平台 key（如外部系统注入的 i18n key）：由调用方直接 `useI18n().t(platformKey)`；不要把外部 key 写入本地 `locales/*.ts`。

## 七、缺翻译时

- 短期用 fallback（默认 zh-CN）；缺翻译条目必须落到 PR 描述里推动补齐，不要靠 `t('xxx', 'fallback')` 长期兜底。

## 八、反例

- ❌ 在 Vue 模板里写死中文文案（如 `<n-button>提交</n-button>`）。
- ❌ 模板里 `t('module.user') + ' - ' + t('form.title')`。
- ❌ 在 `packages/locales/langs/*.json` 里手改——仓库采用 TS composition 写法，应编辑 `packages/locales/src/langs/*.ts`。
- ❌ `defineOptions({ name: 'Xxx' })` 但模板里写 `{{ $t('common.title') }}` —— 用 i18n key。
- ❌ 大量相同英文 defaultMessage 仅靠 description 区分不同中文含义（应改 key 名）。
